01. Problema

Três canais de venda, três formatos de pedido#

Este é um projeto de exemplo para mostrar a estrutura da página. Troque o texto pelo seu.

Cada canal de venda gravava o pedido de um jeito. O time de atendimento precisava abrir três telas para responder uma pergunta simples: onde está o meu pedido?

formatos de pedido diferentes
3
tempo médio de resposta
1,8 s
pedidos corrigidos à mão
12/dia

02. Solução

Um contrato único, validado na entrada#

Todo pedido passa por um schema antes de entrar no sistema. Se o canal manda algo fora do contrato, o erro volta na hora, com o campo exato que falhou.

pedido

export const pedidoSchema = z.object({
  canal: z.enum(["site", "app", "marketplace"]),
  itens: z.array(itemSchema).min(1),
  total: z.number().positive(),
});
app.post("/pedidos", async (req, res) => {
  const pedido = pedidoSchema.safeParse(req.body);
  if (!pedido.success) {
    return res.status(422).json(formatarErro(pedido.error));
  }
  res.status(201).json(await criarPedido(pedido.data));
});

03. Integração

O pedido segue mesmo quando um serviço cai#

O envio para o estoque e para a nota fiscal acontece em fila. Se um serviço externo falha, o pedido não se perde: ele volta para a fila com um novo prazo.

  1. pedido recebido
  2. validação
  3. fila
  4. estoque
  5. nota fiscal
  6. se falhar: nova tentativa em 5 min
